# 电子病历库 vault — 工作规矩

本文件是本目录（及其子目录）的常驻规矩，**任何 AI Agent（Hermes / Codex / Claude Code / Cursor / Copilot / Gemini CLI…）都按这一套干活**。归档流程的完整定义在同仓库的 `skills/health-vault/SKILL.md`；**本文件的规矩优先级更高**，冲突时以本文件为准。

> **非 Hermes 的 Agent 请注意**：完整的归档流程、字段规范与自检规则在 `skills/health-vault/SKILL.md`（及其 `references/`）。**请把它当成必读文档一起读。**
>
> **设计理由**（为什么这么定、哪些地方不能改）见 `8-知识库/设计说明.md` —— 动手改结构前先读它。

## 这是什么

家庭健康档案库：**检查报告 + 就医记录 + 指标 + 用药 + 不适记录**的结构化归档与原图留存。数据属于用户本人，vault 是唯一权威副本。

## 硬边界（永不违反）

- ❌ 不诊断、不做鉴别诊断、不做可能性排序
- ❌ 不给用药建议（不推荐 / 不调整 / 不替换 / 不停药）
- ❌ 不判断紧急度；出现胸痛、呼吸困难、大出血、意识丧失、自杀念头、突发严重神经症状 → **先让用户就医**，再谈归档
- ❌ 不补造数据：缺失写 `[信息缺失]`，推断写 `[推断]` 并说明依据，数值拿不准写 `[待核对]` 并留空
- ✅ 保留不确定性，不替医生把话说圆
- ✅ 每次回答结尾提醒：档案是整理，请与医生确认

## 六条交互规矩

1. **分不清就问** —— 单据类型、患者是谁、机构/日期读不清、项目名不在词表里、是否同一次活动：**一律先问用户**，绝不猜、绝不编。
2. **命名统一走词表** —— 报告项目名只能取自 `8-知识库/项目名规范.md`。遇到词表里没有的：**先问用户** → 定标准名 → 补进词表（连同别名）。禁止同义异写。
3. **多份单据先问归属（跨天必问住院）** —— 一次归档涉及多天 / 多份单据时，**先问归属再归类，绝不自行合并或拆分**：
   - **任意跨天**：问「这几天是不是住院 / 是不是同一次安排」
   - **一批单据的日期落在 7 天以内**（含同一天多张）：问「这是不是同一次看病开的检查合集」
   - **确认同一次 → 合并为 1 个检查活动目录 + 总表 1 行**：目录名与汇总页 frontmatter `日期` 取**其中最早那天的检查日期**，`结束日期` 填最晚那天；就医记录**只加一行**，行日期取这一天（两边同名互链）。若就诊日期与最早检查日不同 → **问用户以哪个为准**
   - **各单据自己的日期一律照抄、不随活动日期改写**：单报告页 `日期` / 原图文件名 / `指标总表.csv` 的 `日期` 都用**这张单子自己的日期**（统一改写会毁掉"近 N 次血常规"的时间线）
   - **确认不是同一次 → 各成一个活动目录**（一天一个）
   - **超过 7 天默认不合并**（除非用户明确说是同一次安排 / 住院）
4. **规矩写在项目里，不写给 agent 的记忆** —— 任何约定、词表、口径的变更都改本文件或 `8-知识库/`；不要依赖记忆（记忆会被压缩磨损）。
5. **冲突必问** —— 同一件事在两处对不上时（例：既往史与检查报告不符；日期/剂量两说；同一检查两次描述不同）：
   - **不自行取舍、不静默覆盖** → 把两处原文并排列出来，问用户「**按哪个？改还是不改？**」
   - 用户定了再动，并且**两处都要落到一致**（只改一处视为待核对）
   - 用户明确说"重复了、以某一处为准"时，另一处保留**链接 + 一句指针**，不删原文
   - **不适用于 `1-基本信息/`** —— 那是基准线，见规矩 6（不追问）
6. **`1-基本信息/` 是基准线：默认只读、不主动问**：
   - **不主动改**：除本人**主动要求**增 / 改 / 删，本页**一个字都不动**；别处新到的数据**不回流**到这里。
   - **不主动问**：发现新数据与本页不一致（例：体重、既往史年份）→ **不问"改不改 / 按哪个 / 要不要同步上去"**，把新数据照常记到它该去的地方（报告页 / 指标 / 体重管理 / 就医记录）就行。
   - **他主动问起时才并列**：把两处并排列出 + 各自出处即可，**不判读、不替他取舍、不追问**。
   - **理由（用户原话）**：数字每次总有细微差别，每次都追问"改不改"效率太低 —— 本页**先做一个基准线**；差异不是冲突，是不同时间的两次记录。
   - 硬边界不变（不补造数据、不诊断）；他主动要求改时照办。

- **新增成员**：库根 `mkdir <名字>/` + 按上面建子目录；**不要**在成员目录里复制 `8-知识库/` 与 `9-模板/`

## 两层记录的关系（核心模型）

- **就医记录**（上位账）= 一次医疗接触，**记在表格里的一行**，不是单独一页：
  - `4-就医记录/就医记录总表.md` 是**唯一手写源**（按年份分小节），`2021.md` 等**年子表由 agent 按总表自动重生成**，结构与总表相同
  - 列固定：`日期 | 机构/医生 | 类型 | 科室 | 症状/主诉 | 判断/结论 | 用药/治疗 | 医嘱 | 下次复查 | 检查报告 | ID`
  - **「用药/治疗」列与 `6-用药/用药流水.md` 是有意交叉**：本列写**本次开了什么药、做了什么处置（快照）**，流水写**这个药吃了多久、调过几次、为什么停**。反查某次就诊时不用点链接就能看到用了什么药
  - `类型` = 体检 / 就诊 / 住院 / 复查 / **自查**
  - 「判断/结论」写**一句话摘要**；完整结论与明细在检查活动页
  - 非药物处置（输液 / 打针 / 雾化 / 换药 / 理疗）也写进本列
  - `ID`（`YYYYMMDD+序号`，如 `20260911a`）用于机器配对：检查活动页 frontmatter 写 `就医ID: 20260911a`。**Markdown 表格行挂不了块 ID，配对靠这一列**
- **检查报告**（下位明细）= 一次检查活动，一个目录：汇总页 + 各单报告页 + 该次原图
- **一次体检 = 总表里一行 + 1 个检查活动目录**（同名互链）
- **同一次看病的多份检查（日期在 7 天内）= 仍是总表一行 + 1 个活动目录**：活动日期取**最早那天**（见交互规矩 3）；只有用户确认不是同一次时才拆成多个活动
- **没有报告的就医**（打针 / 输液 / 只有口头医嘱）→ 总表里一行即可，没有检查活动
- **自查**（没看医生）→ 总表里一行，`类型: 自查`，「判断/结论」写 `自主判断：xxx`，「医嘱 / 检查报告」留空

### 检查活动目录内部

```
2-检查报告/2026-09-11-协和体检/
├── 2026-09-11-协和体检.md       ← 汇总页（人读）：本次做了什么、结论、异常汇总、报告导航
├── 报告/
│   ├── 血常规-2026-09-11.md     ← 单报告页（机器聚合用）
│   └── 心电图-2026-09-11.md
└── attachments/
    ├── 2026-09-11_血常规_原图.png
    └── 2026-09-11_心电图_p1.png
```

**为什么汇总页与单报告页并存**：汇总页给人回看（"这次体检都查了啥"）；单报告页给检索与聚合（"近 10 次血常规"），且是**图像型/描述型报告（心电图、CT、超声、内镜）的唯一载体**——它们进不了数值表。

**合并活动（同一次看病、日期在 7 天内）**：目录名与汇总页「日期」= **最早那天**，`结束日期` = 最晚那天；`报告/` 里的单报告页与 `attachments/` 原图**仍按各自单据的日期**命名，不改成活动日期。

单报告页 frontmatter 必填：

```yaml
类型: 化验 | 影像 | 功能检查 | 病理
项目: <词表标准名>
日期: YYYY-MM-DD
机构:
患者:
检查活动: "[[2026-09-11-协和体检]]"
就医记录: "[[2026-09-11-协和-体检]]"
数值已入表: true | false      # 图像型/描述型为 false
```

## 不适记录（自述，纯记录）

**位置**：`<成员>/3-不适记录/不适记录.md`

- **定位**：日常不舒服时的一句话记录，**没看病、没处理也记**。**不定时、不打卡**。
- **只有四列**（不增不减）：`日期`（几号开始不舒服）/ `不适的感受`（**照原话**）/ `我怎么处理的`（无视 / 准备看病 / 吃药了）/ `持续多久`
- **用途只有一个**：以后真发病了回来**溯源**"之前有没有过这种不适" → 按 `不适的感受` 里的关键词（部位、感觉）做时间线检索，**只检索、不判断、不猜病因**
- **与「自查」的区别**：`自查` = 自己判断 + 自己吃药处理了，算**一次医疗接触**（记 `4-就医记录`）；不适记录 = 只是有不舒服。条目可能后续升级成自查或就诊，**两条并存、不互相覆盖**
- **吃了药**：第三列照写，同时在 `6-用药/用药流水.md` 补一条（`依据: 自主`）

## 用药与药品库

- **药名规范**：统一 `通用名（剂型）`，如 `布洛芬（缓释胶囊）`；需要时后接**大概规格 / 剂量**（用户说明才追加，如 `地芬尼多（片）25mg`），不猜。用户报商品名（优甲乐/芬必得）→ 查库 → **回问确认** → 落通用名；库中没有的药 → 请用户看药盒，不编。
- **用药记录不记「一天几次」（频次）**：本人回忆不准，记了只会产生 `[信息缺失]` 噪声 → **不记、不问、也不留空占位**。用药只记：吃什么药（通用名＋剂型）· 大概规格 / 剂量 · 开始/停/依据/`停止原因`。
- **用药的唯一源头 = `6-用药/用药流水.md`**：`1-基本信息/` **不存任何用药信息**（避免两处重复）；给医生看的用药视图由它派生到 `7-视图/用药记录.md`
- **用药记录位置**：`6-用药/用药流水.md`（按「药」为主线）——覆盖 (a) 长期服用/保健品（顶部「当前在服」表）(b) 看病开的药（开了什么 / 实际怎么吃 / 吃多久）(c) 自我用药（含 `停止原因`）。**就医记录总表的「用药/治疗」列写本次快照，两处有意交叉、都要写**（只更新一处视为待核对）。
- **药品说明书库**（可选）：`〈药品库目录〉/drugs.sqlite`（上万条说明书 + 上万条相互作用），查询走 `〈药品库目录〉/q.py`（建库脚本 `build.py`），用法见 `drug-lookup` 技能。**永远不要把这个库读进上下文**，只用脚本查、只引用命中行。⚠️ 公开可得的中文说明书整理集**许可不明** → **仅本机个人参考，不得再分发**；授权来源见 `8-知识库/用药指南/索引.md`。
- **边界**：只照录说明书原文（适应症/禁忌/不良反应/相互作用 + 风险等级），**不做任何用药判断或建议**；结尾提醒咨询医生/药师。

## 面向医生的病历报告（输出 PDF）

- 素材 = `7-视图/` 三件套 + 本次症状（可从 `3-不适记录` 抽同类不适的时间线）+ 指标时间对比
- 四段结构：① **本次不适（症状描述）** ② **近期用药（最近 N 次）** ③ **相关化验指标（带时间对比，标上涨/下降）** ④ **既往要点**
- **脱敏**：只放 性别 / 年龄段 / 身高体重 / 过敏史 / 慢病 / 用药 / 指标；**不放**全名（用 ××）、身份证、电话、住址、单位
- 输出：HTML + 打印样式 → 用本机可用的 HTML→PDF 方案（无头浏览器打印 / 系统自带工具）导出 **PDF**
- 详细个人信息只留在 `1-基本信息/`，**报告一律用脱敏版**

## 指标总表（`5-指标/指标总表.csv`）

列固定，不增不减：

```
日期,患者,来源类型,机构,检查活动,项目,指标名,值,单位,参考范围,异常,来源笔记
```

- `来源类型`：体检 / 就诊 / 住院 / 复查 / 自查
- **一张总表**："某次就医的数据"按 `检查活动` 或 `来源笔记` 筛；"某指标的近 N 次"按 `指标名` 分组
- 只装**数值型**：图像型/描述型（心电图波形、CT、超声、内镜）不进表，结论写在报告页
- **定性判定值不进本表**：如幽门螺杆菌呼气试验的 DPM 只是那份报告的判定值 → **定性结论（HP 阴性/阳性）写在报告页**
- **体重 / BMI / 体成分这类自测数据不进本表**：身高留在 `1-基本信息/`；体重、BMI、体脂率等**进 `<成员>/8-体重管理/体重管理总表.csv`** ——**本表只装"有检验报告"的临床数值**
- 数值照抄（含单位），**不换算、不推断**；缺失留空
- **同一指标在不同单据里单位写法不一致时，照样各抄各的（不换算、不统一）**——例：红细胞压积一张单印 `0.49 %`、另一张印 `0.5250 L/L`；血小板压积一张印百分数 `0.25`、另一张印分数 `0.003000 L/L`。看趋势时自己留意单位

## 体重管理（`<成员>/8-体重管理/`）

**放什么**：**自己测的**体态数据（体重 / 体成分），高频、无报告、无参考范围 —— 与"有检验报告的临床数值"分开，曲线才干净。

**文件**：`<成员>/8-体重管理/体重管理总表.csv`（唯一数据源，长表：**一次测量 = 一组行，一行一个指标**）。
**不存原图**：体脂秤截图**只提取文字**，不留图、不复制进库 —— 复查时看表即可，存图没有意义。

**列固定，不增不减**：

```
日期,时间,患者,来源类型,项目,机构/设备,指标名,值,单位,参考范围,判定,笔记
```

- `来源类型`：**自测**（家用设备）／体检／就诊 —— 「自测」是本目录专有值，**不进 `5-指标` 的来源类型枚举**
- `项目`：词表标准名（当前只有 `体脂秤`）
- `单位` / `参考范围`：**设备/单据上印了才写**；App 只给定性标签时 `参考范围` 留空
- `判定`：**照抄 App 的标签**（标准 / 偏高 / 过高 / 偏低），不自己判读、不换算
- `指标名`：一律取自 `8-知识库/项目名规范.md` 的「体重管理指标名」，禁止同义异写
- 同一天多次称重：**逐条追加，不合并、不取平均**
- **不建检查活动、不加就医记录、不进 `5-指标`** —— 它不是一次医疗接触

## 归档流程（9 步）

> **开工前先 `git status`**：工作区应干净。若某文件近期被**其他会话**改过（工具会提示 sibling 改动），**先读最新内容 + `git diff HEAD` 比对**，再用定点 `patch` 改；**绝不整篇重写别人刚改过的文件**（并发会话会冲掉未提交的改动）。
>
> **另一条入口：只汇报不适（没看病）** → 追加 `3-不适记录/不适记录.md` 一行（照原话，缺的当场问）；若同时自己吃了药 → 按第 6b 步记 `6-用药/用药流水.md`。**不建检查活动、不加就医记录行**。
>
> **再一条入口：体重管理记录（体脂秤 / 身体成分截图）** → 追加 `8-体重管理/体重管理总表.csv` 一组行（一次测量 = 一组），**只提取文字、不留原图**。**不建检查活动、不加就医记录、不进指标总表**（细则见上一节）。

1. 读图 → 确认 **类型 / 机构 / 日期 / 患者 / 项目名**（任何一项不确定 → 问用户）
2. 多天 / 多份单据（日期落在 7 天内）→ **先问归属**：是不是住院、是不是同一次安排、是不是同一次看病的检查合集。确认同一次 → **合并为一个检查活动**，**活动日期（目录名 + 汇总页「日期」）取最早那天**，`结束日期` 填最晚那天；确认不是 → 各成一个活动
3. 在 **`4-就医记录/就医记录总表.md`** 加一行（填 ID），并按年**重生成该年份子表**（子表永远由总表派生）
4. 建或更新**检查活动目录**（`2-检查报告/`）：汇总页 + `报告/` + `attachments/`
5. **复制原图**进该活动 `attachments/`，按 `YYYY-MM-DD_<标准名>_原图[_pN].ext` 重命名（上传缓存目录里的图只是临时文件，**必须复制**）。**一张单据含多个检查项目时，项目名用 `+` 连接**（按单据上的项目顺序），如 `2024-12-02_电解质+肾功_原图.jpg`；各报告页共用这一张原图，用任一项目名都能捞到它
6. 数值型 → 追加 `指标总表.csv` 行；图像型/描述型 → 原图内嵌 `![[...]]` + 写结论（`数值已入表: false`）
6b. **用药**：就医记录行填「用药/治疗」快照；同时在 `6-用药/用药流水.md` 按药追加/更新条目（动作 / 剂量 / `依据`=医嘱或自主 / `停止原因` / 来源链接）；长期服用的同时更新顶部「当前在服」表
7. 更新 `7-视图/`：`用药记录.md`、`化验指标追踪.md` 由上游派生重生成；`主档案.md` 追加更新（只追加/更新，不重写历史）
8. 对照 `skills/health-vault/references/validation_rules.md` + `completeness_checklists.md` 自检，列"待核对"
9. `git add -A && git commit -m "归档: <事件>"`

## 逆向导出（能力约定，靠命名规则保证）

- 原图命名固定为 `YYYY-MM-DD_<标准名>_原图[_pN].ext` → 才能按模式一次收全；一张单据含多个项目时写 `A+B`（如 `2024-12-02_电解质+肾功_原图.jpg`），用任一项目名都能捞到同一张原图
- 例：近 10 次心电图原图
  `find 2-检查报告 -path "*attachments*" -name "*心电图*" | sort | tail -10`
- 例：近 10 次血常规报告页
  `find 2-检查报告 -name "血常规-*.md" | sort | tail -10`（或按 frontmatter `项目:` 筛）
- 例：某部位的不适历史（溯源）
  `grep -n "太阳穴\|头疼" 3-不适记录/不适记录.md | sort`
- 收齐后可打包 zip 交给用户，或生成对照页

## 检索优先序（回答健康问题时）

1. **先查本 vault**：直接读文件（快、准、结构化），或 Obsidian 自带的 CLI / 搜索
2. 需要"当时的原话/上下文"时，再查历史会话记录（含聊天软件、桌面端来源）
3. 两边都给出来处（笔记路径 + 会话出处）

## 会话怎么用（用户约定）

- **会话只是投递窗口，不是分拣口**：往哪个会话说都行 —— agent 按单据类型自动分发到 `2-检查报告` / `3-不适记录` / `4-就医记录` / `5-指标` / `6-用药`。**用户不需要为"该放哪个会话"纠结**。
- **开几个会话都行**：纯文字会话上下文涨得很慢，一个会话能用很久；**带照片的会话要短**（图片每轮重发，涨得快，最容易触发压缩）→ 一批单据一个会话，归档完开新会话。
- **归档完成后，删掉或归档那个会话都不影响库** —— 数据落在磁盘文件里，不在会话里。**但必须等 agent 明确回复"已归档 + 已 commit"再动**（删太早会丢掉"当时的原话"这一层对照）。
- **想留后路就点「归档」**（可恢复、只是从列表隐藏）；**「删除」不可逆**，只在确认已归档后才用。
- 建议保留**一个常驻会话做问询**；随手记录（不适、长期药变动）直接说在那个会话里即可。
- **删 / 归档会话永远不动库**；库只会在 agent 归档时变化，且每次都 commit。
