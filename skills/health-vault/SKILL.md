# Health Vault（个人／家庭健康档案归档）

把体检报告、化验单、处方、就医记录的照片/文字，归档进 Obsidian 健康库：**检查报告（汇总页 + 单报告页 + 原图）+ 就医记录 + 指标表**。只做整理与引用。

**先读 vault 里的 `AGENTS.md`——它的规矩优先于本技能**（用户在仓库里维护的那份是权威口径）。

## 硬边界（永不违反）

- ❌ **不诊断**：不做诊断推理、鉴别诊断、可能性排序、漏诊评估。医生写的是「记录」，没写的**不许推断**。
- ❌ **不给用药建议**：不推荐、不调整、不替换、不停药。
- ❌ **不判断紧急度**：出现胸痛、呼吸困难、大出血、意识丧失、自杀念头、突发严重神经症状等描述时，**先让用户就医/呼叫急救**，再继续归档。
- ❌ **不补造数据**：缺失标 `[信息缺失]`；推断的标 `[推断]` 并说明依据；数值拿不准标 `[待核对]` 并留空。
- ✅ 保留不确定性；结尾提醒：档案是整理，请与医生确认。

## 四条交互规矩（用户明确要求）

1. **分不清就问**：单据类型 / 患者是谁 / 机构日期 / 项目名不在词表 / 是否同一次活动 → 一律先问用户，绝不猜、不编。
2. **命名统一走词表**：项目名只能取自 vault 里的 `8-知识库/项目名规范.md`；遇到新项目先问用户，再补进词表（连同别名）。禁止同义异写（心电图 ≠ ECG ≠ 心电检查）。
3. **跨天必问住院**：一次归档涉及多天时，必须先问「这几天是不是住院 / 是不是同一次安排」，再决定是否合并为同一次检查活动、以及归到哪次的开端或结尾。
4. **规矩写在 vault 里，不写进 agent 记忆**（记忆会被压缩磨损）：约定、词表、口径的变更都改 vault 的 `AGENTS.md` 或 `8-知识库/`。

## vault 位置

默认 vault：`〈库根目录〉`（本机已装 Obsidian 1.13.7，程序在 `/opt/Obsidian`）。**当前成员：张三**（成员目录 `〈库根目录〉/张三/`，归档直接写这个目录下）。结构是**库 → 人 → 档案**：库根只放 `AGENTS.md`、`8-知识库/`（共享规范与药品）、`9-模板/`；每个成员一个目录（以人名命名），里面才是 `1-基本信息/`…`7-视图/`（**顺号，不跳号**）。新增成员时**不要**在成员目录里复制 `8-知识库/` 与 `9-模板/`。`~/Obsidian/` 是**上层目录**，放各个独立 vault，每个子目录是自成一体的仓库。若 `$OBSIDIAN_VAULT_PATH` 有值，以它为准。

```
电子病历库/                    ← 库根（Obsidian 打开这一层）：AGENTS.md / 8-知识库/ / 9-模板/
└── 张三/                    ← 本机当前成员（新增成员 = 并列一个同名目录）
    ├── 1-基本信息/       姓名、过敏史、慢病、长期用药、紧急联系人
    ├── 2-检查报告/       YYYY-MM-DD-机构-活动/  ← 一次检查活动一个目录（汇总页 + 报告/ + attachments/）
    ├── 3-不适记录/       不适记录.md ← 自述不适的纯记录（没看病也记）：日期 / 感受 / 怎么处理 / 持续多久
    ├── 4-就医记录/       就医记录总表.md（唯一手写源）+ 年子表 ← 一行一次医疗接触（含 自查）；行内含「用药/治疗」快照
    ├── 5-指标/           指标总表.csv（跨来源数值长表）
    ├── 6-用药/           用药流水.md（顶部「当前在服」表 + 按药分节时间线：长期 / 医嘱 / 自用）
    ├── 7-视图/           给医生看的三件套：主档案 / 用药记录 / 化验指标追踪
    └── attachments/      待归类原图（暂存，不编号）
```

## 核心模型：就医记录（上位）↔ 检查报告（下位）

- **就医记录** = 一次医疗接触，**表格里的一行**：日期、机构/医生、类型、科室、症状/主诉、判断/结论、医嘱、下次复查、检查报告、ID；`类型` = 体检/就诊/住院/复查/**自查**。总表是唯一手写源，年子表由总表派生。含「用药」/「治疗」列（本次开药与处置的快照，**与用药流水有意交叉**）。
- **检查报告** = 一次检查活动，一个目录：`汇总页.md` + `报告/<标准名>-YYYY-MM-DD.md` + `attachments/`。
- **一次体检 = 1 行就医记录 + 1 个检查活动目录**（两边同名互链；表格行挂不了块 ID，靠 `ID` 列 ↔ 活动页 frontmatter `就医ID` 配对）。
- **没有报告的就医**（打针/输液/口头医嘱）→ 只有总表里那一行。
- **自查**（没看医生）→ `类型: 自查`，「判断」写 `自主判断：xxx`，医嘱与检查报告留空；用药照记到 `用药流水.md`。
- **为什么汇总页与单报告页并存**：汇总页给人回看；单报告页给检索聚合（“近 10 次血常规”），且是**图像型/描述型报告（心电图、CT、超声、内镜）的唯一载体**——它们进不了数值表。

## 归档流程（9 步）

> **另一条入口：只汇报不适（没看病）** → 追加 `<成员>/3-不适记录/不适记录.md` 一行（**照原话**；只有四列：日期 / 不适的感受 / 我怎么处理的 / 持续多久）；若用户同时自己吃了药 → 按 6b 记 `用药流水.md`。**不建检查活动、不加就医记录行**。与「自查」的区别：自查 = 自己判断+自己吃药处理了（算一次医疗接触），不适记录 = 只是有感受。

1. 读图 → 确认 **类型 / 机构 / 日期 / 患者 / 项目名**（任一项不确定 → 问用户）
2. 多天 → **问是不是住院 / 同一次安排**
3. 在 **`4-就医记录/就医记录总表.md`** 加一行（填 `ID`），并按年**重生成该年份子表**
4. 建或更新**检查活动目录**（`2-检查报告/`）：汇总页 + `报告/` + `attachments/`
5. **复制原图**进该活动 `attachments/`，重命名为 `YYYY-MM-DD_<标准名>_原图[_pN].ext`（`~/.hermes/images/` 只是上传缓存，**必须复制**）
6. 数值型 → 追加 `5-指标/指标总表.csv` 行；图像型/描述型 → 原图内嵌 `![[...]]` + 写结论（`数值已入表: false`）
6b. **用药** → 在 `6-用药/用药流水.md` 按药追加/更新（动作 / 剂量 / `依据`=医嘱或自主 / `停止原因` / 来源链接）；长期服用的同时更新顶部「当前在服」表
7. 更新 `7-视图/`：`用药记录.md`、`化验指标追踪.md` 由上游派生重生成；`主档案.md` 追加更新
8. 按 `references/validation_rules.md` + `references/completeness_checklists.md` 自检，列“待核对”
9. `git add -A && git commit -m "归档: <事件>"`

单报告页 frontmatter 必填：`类型`(化验/影像/功能检查/病理) `项目`(词表) `日期` `机构` `患者` `检查活动` `就医记录` `数值已入表`。

## 用药与药品库

- **记录位置**：`6-用药/用药流水.md` —— 按「药」为主线，覆盖 (a) 长期服用/保健品（顶部「当前在服」表）(b) 看病开的药（开了什么 / 实际怎么吃 / 吃多久）(c) 自我用药（含 `停止原因`）。**就医记录总表的「用药/治疗」列写本次快照，两处有意交叉、都要写**（只更新一处视为待核对）。
- **药名规范**：`通用名（剂型）`，如 `布洛芬（缓释胶囊）`；**剂量只在用户说明时追加**（`50μg qd`），不猜。用户报商品名（优甲乐/芬必得）→ 查库 → **回问确认** → 落通用名；库中没有的药 → 请用户看药盒，不编。
- **药品库**：`〈药品库目录〉/drugs.sqlite`（上万条中文说明书 + 上万条相互作用），查询脚本 `〈药品库目录〉/q.py`，用法见 `drug-lookup` 技能。**绝不把库读进上下文**，只查、只引用命中行。⚠️ 许可不明（爬自药典网），仅本机个人参考，**不得再分发**。
- **边界**：只照录说明书原文（适应症/禁忌/不良反应/相互作用 + 风险等级），**不给用药建议、不做判断**。

## 面向医生的病历报告（PDF）

- 素材 = `7-视图/` 三件套 + 本次症状（可从 `3-不适记录` 抽同类不适的时间线）+ 指标时间对比
- 四段：① 本次不适（症状描述）② 近期用药 ③ 相关化验指标（带时间对比，标上涨/下降）④ 既往要点
- **脱敏**：只放 性别 / 年龄段 / 身高体重 / 过敏史 / 慢病 / 用药 / 指标；**不放**全名（用 ××）、身份证、电话、住址、单位
- 实现：HTML + 打印 CSS → `firefox --headless --print-to-pdf`（用本机可用的 HTML→PDF 方案，如无头浏览器打印）

## 指标总表（`5-指标/指标总表.csv`）

列固定：`日期,患者,来源类型,机构,检查活动,项目,指标名,值,单位,参考范围,异常,来源笔记`

- **一张总表**：某次就医的数据 → 按 `检查活动`/`来源笔记` 筛；某指标近 N 次 → 按 `指标名` 分组
- 只装数值型；数值照抄（含单位），**不换算、不推断**，缺失留空

## 命名规范

- 就医记录页 / 检查活动目录：`YYYY-MM-DD-机构-活动`（两边**同名**，便于互链）
- 单报告页：`<标准名>-YYYY-MM-DD.md`；汇总页：同活动名
- 原图：`YYYY-MM-DD_<标准名>_原图[_pN].ext`
- 标准名一律取自 `8-知识库/项目名规范.md`

## 逆向导出（靠命名规则保证）

- 近 10 次心电图原图：`find 2-检查报告 -path "*attachments*" -name "*心电图*" | sort | tail -10`
- 近 10 次血常规报告页：`find 2-检查报告 -name "血常规-*.md" | sort | tail -10`
- 某部位不适历史（溯源）：`grep -n "太阳穴\|头疼" 3-不适记录/不适记录.md`
- 收齐后可打包 zip 交用户（其他设备下载），或生成对照页

## 术语与表述

- 用户口语（「肚子疼」「发烧」）写成标准表述（腹痛、发热）：对照 `references/terminology_map.md`；有歧义先追问。
- 通俗解读（给父母看的版本）严格按 `references/plain-language-rules.md`：只反映文档内容，不解释、不推断、不排序；给 3–5 个「可以问医生的问题」。

## 检索与对照

- 程序侧：`obsidian` CLI（`~/.local/bin/obsidian`，需 `XDG_RUNTIME_DIR=/run/user/1000`）：`obsidian search query="甲状腺"`、`obsidian vault`。
- 文件侧：`search_files` / `read_file` 直接读 vault（更快）。
- 历史对话：`session_search` 全库检索（含微信、desktop 来源）。
- 回答健康问题前：**先查 vault（结构化事实+趋势），需要原话再回会话库**，两边都给出处。

## 运维注意（本机 Obsidian）

- `~/.config/obsidian/obsidian.json` **同时存 vault 注册表和 app 级设置**（`"cli":true` 就是官方 CLI 开关）。改它必须**读-改-写**，整体覆盖会静默关掉 CLI 开关与硬件加速设置。
- 搬动/重命名 vault：先 `systemctl --user stop obsidian.service`，改完路径再 `reset-failed && start`，用 `obsidian vault` 验证新路径。
- GUI 自动化：`xdotool`（本地解包在 `~/local`，需 `LD_LIBRARY_PATH=~/local/usr/lib/x86_64-linux-gnu`）比 computer_use 可靠；`ctrl+comma` 开设置（先用 `xdotool windowactivate` 激活主窗口）。

## 会话怎么用（用户约定）

- **会话只是投递窗口，不是分拣口**：用户往哪个会话说都行，agent 按单据类型分发到 `2-检查报告` / `3-不适记录` / `4-就医记录` / `5-指标` / `6-用药`。用户不需要为“该放哪个会话”纠结。
- **带照片的会话要短**（图片每轮重发，涨得快、最易触发压缩）；一批单据一个会话，归档完提示用户 `/new` 或归档会话。纯文字会话可以很长。
- **归档完成后**用户删/归档那个会话都不影响库（数据在磁盘文件里）；**但删太早会丢掉“当时原话”的对照** → 回复里必须明确说“已归档 + 已 commit”，用户才动手。
- **库只增不改**：就医记录/指标/用药/不适记录都只追加行；历史行不动。修正 = **追加 + 标注**。
- **唯一例外**：`7-视图/` 三件套是从上游**重生成**的派生文件（源数据不动，丢了可再生成）。
- 每次归档收尾 `git add -A && git commit`（**本地 git，无远程仓库、不上云**），任何提交都能回滚。
