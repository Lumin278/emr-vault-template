# 病历管理 · 电子病历库

> **中文名：病历管理**（也叫 电子病历库 / 健康档案库）｜**英文名：EMR Vault Template**｜**仓库名：`emr-vault-template`**
>
> 用 **Obsidian + AI Agent（Hermes）** 把体检报告、化验单、就医记录、用药史整理成一套**可检索、可追溯、可带走**的个人 / 家庭病历库。
>
> 本仓库是**框架与模板**：归档规则 + Agent 技能 + 空库骨架。**不含任何真实病历数据。**
>
> 🔎 关键词：病历管理 · 电子病历 · 健康档案 · 体检报告 · 化验单 · 就医记录 · 用药记录 · 用药流水 · 体重管理 · 脱敏病历报告 · Obsidian · AI Agent · Agent 技能

---

## 它解决什么问题

体检报告拍完照就烂在相册里，化验单堆在抽屉里，医生问"这个症状以前有过吗""这个药吃了多久"，全靠回忆。

这个模板让 AI Agent 当你的**归档员**，把散落的单据变成结构化的档案：

| 痛点 | 这个库怎么答 |
|---|---|
| 三个月前那张血常规去哪了 | `2-检查报告/` 按"一次检查活动一个目录"存放，原图一并留存 |
| 我今年看了几次病 | `4-就医记录/` 总表一行一次，症状/结论/用药/医嘱全在 |
| 这个药我到底吃了多久、中间停过吗 | `6-用药/` 按"药"为主线流水，含调量、停止原因 |
| 肝功这几年是涨还是跌 | `5-指标/` 跨来源数值长表 → 看趋势 |
| 我最近体重 / 体脂怎么变的 | `8-体重管理/` 自测体态长表（与临床指标分开，曲线才干净） |
| 医生问"以前有没有这种不舒服" | `3-不适记录/` 平时随手记，按部位/感觉回溯时间线 |
| 换个医生就要从头讲一遍病史 | `7-视图/` 三件套 + **脱敏 PDF 报告**，直接带去诊室 |

**边界（写进规则里，永不违反）**：只做**整理与检索** —— ❌ 不诊断、❌ 不给用药建议、❌ 不判断紧急度、❌ 不补造数据。缺失标 `[信息缺失]`，推断标 `[推断]`，不确定标 `[待核对]`。

## 库的结构：库 → 人 → 档案

```
我的电子病历库/                    ← Obsidian 打开这一层
├── AGENTS.md                      ← 归档规则（Agent 每次工作都读它，优先级最高）
├── README.md  IDEA.md
├── 8-知识库/                      ← 全库共享：受控词表、设计说明、选型调研、药品索引
├── 9-模板/                        ← 全库共享：归档模板
└── 张三/                          ← 一个成员一个目录（改成真实姓名）
    ├── 1-基本信息/                姓名、过敏史、慢病、紧急联系人（**基准线，默认只读**）
    ├── 2-检查报告/                一次检查活动一个目录（汇总页 + 报告/ + attachments/ 原图）
    ├── 3-不适记录/                自述不适的流水账（没看病也记）
    ├── 4-就医记录/                总表 + 年子表，一行一次医疗接触
    ├── 5-指标/                    指标总表.csv（跨来源数值长表）
    ├── 6-用药/                    用药流水（长期 / 医嘱 / 自用）
    ├── 7-视图/                    给医生看的三件套（派生文件）
    ├── 8-体重管理/                体重管理总表.csv（自测体态数据；不进 5-指标、不留原图）
    └── attachments/               待归类原图暂存
```

**编号 1–8 就是阅读顺序**；`8-知识库` / `9-模板` 是**全库共享，只有一份**（加成员时不复制）。注意成员级 `8-体重管理/` 与库根 `8-知识库/` **同号不同层**，引用时带路径。

## 五条数据主线

| 视角 | 载体 | 回答的问题 |
|---|---|---|
| **感受** | `3-不适记录` | 我什么时候有过什么不舒服？这次是不是老毛病？ |
| **事件** | `4-就医记录` + `2-检查报告` | 什么时候看了什么病、结果如何、用了什么药、原件在哪 |
| **药物** | `6-用药/用药流水` | 这个药吃了多久、调过几次、为什么停 |
| **数值** | `5-指标/指标总表.csv` | 某个指标这几年的走势 |
| **体态** | `8-体重管理/体重管理总表.csv` | 体重 / 体成分怎么变的（画曲线用） |

## 几个关键设计（为什么这么做）

- **一次检查活动 = 一个目录**：目录里既有给人看的**汇总页**，也有每张单子的**独立报告页**。汇总页负责"这次体检都查了啥"，独立页负责"近 10 次血常规"这类聚合检索 —— 而且是心电图/CT/超声这类**图像型报告的唯一载体**（它们进不了数值表）。
- **7 天内的多张单子先问、再合并**：一周内的几张单子通常是同一次看病开出去的检查 → 用户确认后合并成**一个活动 + 就医记录一行**，活动日期取**最早那天**、`结束日期` 记最晚那天；**但每张单子自己的日期照抄不改**（否则"近 N 次血常规"的时间线就失真了）。归属一律由用户确认，Agent 不自行合并或拆分。
- **原图命名规范化**：`YYYY-MM-DD_<项目>_原图[_pN].ext`（一张单子含多个项目时写 `A+B`）。因此可以一条命令取全："近 10 次心电图原图"。
- **受控词表**（`8-知识库/项目名规范.md`）：报告项目名只能取自词表，禁止"心电图 / ECG / 心电检查"混用 —— 这是**未来能不能自动统计的地基**。词表里没有的项目，Agent 必须先问用户再定名。
- **表格行靠 `ID` 列配对**：Markdown 表格行挂不了块 ID，所以用 `就医ID` 双向配对（就医记录行 ↔ 检查活动页）。
- **只增不改**：历史行不动，修正一律"**追加 + 标注**"。唯一例外是 `7-视图/` 三件套 —— 它们是从上游重生成的派生文件（源数据不动）。
- **用药两处有意交叉**：就医记录那一行的「用药/治疗」列写**本次快照**（这次开了什么），`6-用药/用药流水.md` 写**这个药的一生**（吃多久、调过几次、为什么停）。两处都要写，只更新一处算待核对。
- **不做打卡**：不适记录是"想说的时候说一句"，用药**不记频次**（一天几次记不准，只记药名 + 大概剂量 + 时间线）——**一个没人愿意用的记录系统等于没有**。
- **`1-基本信息/` 是基准线**：默认只读，Agent 不主动改、也不问"要不要同步最新数据"；后来的测量各落各的位置，要看对比就两边并排。
- **每次归档都提交 git**：库是本地 git 仓库，任何一次改动都可以回滚。**注意：纯本地，不需要 GitHub。**
- **面向医生的报告**：`7-视图/` 三件套 + 本次症状 + 指标时间对比，**脱敏后**输出 PDF（只留性别 / 年龄段 / 身高体重 / 过敏史 / 慢病 / 用药 / 指标；不放全名、身份证、电话、住址）。
- **会话只是投递窗口**：往哪个会话丢单据都行，Agent 按单据类型自动分发到对应目录。

## 谁来当归档员（Agent 兼容性）

这套东西**不绑定某一个 AI Agent**：

| 你的 Agent | 怎么用 |
|---|---|
| **Hermes Agent** | 把 `skills/health-vault/`、`skills/drug-lookup/` 拷进 `~/.hermes/skills/` —— 自动加载，最省心 |
| **任何读 `AGENTS.md` 的 Agent**（OpenAI Codex、Cursor、Copilot、Claude Code、Gemini CLI…） | 直接把 `vault-template/` 当工作目录，它会读到 `AGENTS.md` 里的规矩；**同时让它读同仓库的 `skills/health-vault/SKILL.md`**（归档流程、字段规范、自检规则都在那里） |
| **Claude 系（Agent Skills 格式）** | `SKILL.md` 与 Anthropic Agent Skills 同源格式，可直接放进 skills 目录 |
| **不用 Agent** | 完全可以 —— 全库都是 Markdown 表格，照 `9-模板/` 自己填也能用（这正是选 Obsidian 的原因） |

**已附带的"入口文件"**（各家约定的文件名不同，所以每种都放了一个，内容只有几行、都指向同一份规矩）：

```
AGENTS.md                            ← Codex / Cursor / 通用（仓库级说明 + 阅读顺序）
CLAUDE.md                            ← Claude Code
GEMINI.md                            ← Gemini CLI
.github/copilot-instructions.md      ← GitHub Copilot
.cursor/rules/emr-vault.mdc          ← Cursor 规则
```

仓库根和 `vault-template/` 里各有一套 —— 无论你的 Agent 从哪一层开始工作，都能找到自己的入口。

**获取方式任选**：

1. 点仓库右上角 **Use this template** —— 生成你自己的一份（不带走本仓库的提交历史）
2. `git clone` —— 想跟随后续更新就用这个
3. **下载 ZIP 解压** —— 最省事，不需要装 git

**核心不变的东西**：库是你自己磁盘上的文件，Agent 只是工人。换 Agent、换机器、哪怕十年后 —— 档案还在原地。

## 怎么开始

### 方式 A：Hermes Agent 一行命令（推荐）

发布到 GitHub 之后（用户名 `Lumin278` 已填好；如果仓库名不是 `emr-vault-template`，把命令里那段换掉即可）：

```bash
hermes skills install Lumin278/emr-vault-template/health-vault --yes
hermes skills install Lumin278/emr-vault-template/drug-lookup  --yes
```

Hermes 会自动在仓库里定位到 `skills/health-vault/SKILL.md`，并连同 `references/`、`templates/` **整个目录**一起装进 `~/.hermes/skills/`。

> 也支持直接指向 SKILL.md 的 URL：
> `hermes skills install https://raw.githubusercontent.com/Lumin278/emr-vault-template/main/skills/health-vault/SKILL.md`

### 方式 B：ZIP / 本地一键脚本

```bash
bash install.sh                 # Linux / macOS：装技能
bash install.sh --with-vault    # 顺便把空库骨架复制到 ~/电子病历库
bash install.sh --claude        # 顺便装给 Claude Code（~/.claude/skills）
```

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1              # Windows
powershell -ExecutionPolicy Bypass -File install.ps1 -WithVault   # 顺便建空库
```

（脚本不会覆盖已存在的技能，除非加 `--force` / `-Force`）

### 方式 C：手动，不用脚本

```bash
cp -r skills/health-vault  ~/.hermes/skills/     # 归档流程 + 字段规范 + 校验规则
cp -r skills/drug-lookup   ~/.hermes/skills/     # 药品说明书查询（数据自备，见下）
cp -r vault-template       ~/我的电子病历库        # 空库骨架
```

## 建库之后

用 Obsidian 打开 `~/我的电子病历库`，然后把 `张三/` 重命名成你的名字，并修改根目录 `AGENTS.md` 里的：

- 库根路径
- 当前成员名
- （多人时）新增成员目录

顺便把 `8-知识库/项目名规范.md` 的「机构名」一节改成你自己的医院写法，把词表慢慢养成你的（这是这个库越用越值钱的地方）。

## 开始投单据

对着这个库说一句"帮我归档"，然后把单据照片发进来就行。Agent 会先跟你确认**单据类型 / 机构 / 日期 / 项目名 / 是不是同一次看病**，再动手写。归档完会给回执：

> 已归档（commit `xxxxxx`）：就医记录 +1 行 · 报告页 3 个 · 指标 +34 行 · 原图 3 张

## 医生报告

需要时跟 Agent 说"生成一份面向医生的病历报告"，它会按脱敏规则出一份 PDF。

## 关于药品数据（重要）

`skills/drug-lookup` 与 `tools/` 里的脚本（`build.py` / `q.py`）是**查询工具**，它们操作的是一个**本地 SQLite 药品说明书库**（说明书的适应症 / 禁忌 / 不良反应 / 药物相互作用 + 相互作用配对与风险等级）。

**本仓库不附带任何药品数据**，原因有二：体积（数十 MB）与**版权/许可**（公开可用的中文说明书数据集多为非授权整理）。请自行准备数据源，或直接使用 RxNorm / RxNav / openFDA 等有明确授权的接口，再按 `tools/build.py` 里的表结构导入。

**无论数据从哪来，Agent 的边界不变**：只照录说明书原文，**不做任何用药判断或建议**。

## 隐私警告 ⚠️

**不要把装满真实病历的库推到公开仓库。**

- 建议：真实库**只留在本机**（本模板默认纯本地 git，无远程仓库），需要用别的设备看就打包一份副本。
- 若要上云，务必用**私有仓库**，并且清楚：健康数据一旦公开就是永久的、删不掉的（会被 fork、被爬、被索引）。
- 本仓库里的示例成员名字（`张三`）、基本信息、各表格**均为占位示例**，不含任何真实数据。

## 硬边界（给使用者的话）

这套东西是**整理工具**，不是医疗工具。它不会告诉你得了什么病、该不该吃药、要不要停药、症状严不严重 —— 这些请找医生。
